01 / Зачем

Почему бэкап — не опция, а необходимость

Сайт теряют не только из-за взлома

Причины потерять сайт банальнее, чем кажется: случайно удалённая таблица в базе, сбой диска на хостинге, ошибка при обновлении плагина, человеческий фактор — кто-то из команды нечаянно стёр не ту папку. Взлом — далеко не самая частая причина.

Для статического сайта на GitHub Pages риск ниже — вся история изменений уже хранится в Git. Но если есть база данных, личный кабинет, загруженные пользователями файлы — без отдельного бэкапа восстановить это после сбоя невозможно.

03 / Автоматизация

Автоматизация — иначе бэкапов не будет

Вручную бэкапы делают ровно один раз

01
Настройте регулярный dump базы данныхCron-задача раз в сутки — для PostgreSQL это одна команда pg_dump, для MySQL — mysqldump
02
Отправляйте копию за пределы сервераВ облачное хранилище (S3-совместимое) — если сломается сам сервер, локальная копия бэкапа тоже пропадёт вместе с ним
03
Настройте уведомление об ошибке бэкапаЕсли задача упадёт молча, вы узнаете об этом только в момент, когда бэкап реально понадобится
04
Периодически проверяйте восстановлениеБэкап, который ни разу не восстанавливали, — это бэкап, в котором вы не уверены
04 / Правило

Правило 3-2-1

Стандарт индустрии, который реально работает

3 копии данныхОригинал плюс минимум две резервные копии
2 разных носителяНапример, диск сервера и облачное хранилище — не всё в одном месте
1 копия вне основной площадкиЕсли сгорит дата-центр целиком — хотя бы одна копия должна быть в другом месте
Плюс версионированиеХраните бэкапы за несколько последних дней, а не только самый свежий — на случай, если проблема обнаружится не сразу
05 / FAQ

Частые вопросы

Короткие ответы на главное

Как часто нужно делать бэкап?

Зависит от того, как часто меняются данные. Для сайта с активным личным кабинетом — раз в сутки минимум, для редко обновляемого контента хватит и раза в неделю.

Нужен ли бэкап статическому сайту на GitHub Pages?

История коммитов Git уже фактически является бэкапом кода. Дополнительно стоит подумать о бэкапе, только если есть внешние сервисы — например, база подписчиков рассылки.

Сколько хранить старые бэкапы?

Обычная практика — хранить ежедневные копии за последние 7 дней, еженедельные за месяц и ежемесячные за год. Это баланс между надёжностью и объёмом хранилища.
