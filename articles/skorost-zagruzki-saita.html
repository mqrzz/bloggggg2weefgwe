01 / Сравнение

Почему статика быстрее WordPress и Tilda

Разница — в том, что происходит на сервере до ответа

Когда открывают страницу на WordPress, сервер на лету: подключается к базе данных, находит нужную запись, собирает HTML из десятков PHP-шаблонов и плагинов — и только потом отдаёт готовую страницу браузеру. Каждый плагин добавляет свои JS- и CSS-файлы, даже если использует их одна кнопка внизу страницы.

Статический HTML-файл сервер просто отдаёт как есть — без сборки на лету. Конструкторы вроде Tilda добавляют к этому свой JS-фреймворк для редактора, который продолжает грузиться даже на опубликованном сайте, хотя он там уже не нужен.

Без сборки на лету
HTML отдаётся сразу, без обращений к БД
Меньше кода
Нет лишних плагинов и неиспользуемого JS редактора
Меньше TTFB
Время до первого байта — часто в разы ниже, чем у CMS
02 / Изображения

Оптимизация изображений

Обычно именно они — самая тяжёлая часть страницы

ФорматКогда использовать
WebPФото и сложные изображения — на 25–35% легче JPEG при том же качестве
AVIFЕщё легче WebP, но чуть медленнее кодируется — подходит для главных hero-картинок
SVGИконки, логотипы, простая графика — векторный формат, весит килобайты
PNGТолько если нужна прозрачность и WebP не подходит

Помимо формата важны два атрибута: loading="lazy" откладывает загрузку картинок ниже экрана, а width/height резервируют место под изображение, чтобы страница не «прыгала» при загрузке.

<img src="photo.webp"
     width="1200" height="800"
     loading="lazy"
     alt="Описание изображения">
03 / Кэш и CDN

Кэширование и CDN

Отдавайте файлы из точки ближе к пользователю

CDN (Content Delivery Network) — это сеть серверов по всему миру. Файлы вашего сайта копируются на серверы рядом с пользователем — и загружаются быстрее, чем если бы каждый раз ехали с одного сервера в другой конец света.

  • Кэш браузера — статичные файлы (CSS, JS, шрифты) не перекачиваются при повторном визите
  • Cloudflare — бесплатный CDN, который заодно защищает от части атак
  • GitHub Pages — сам раздаёт файлы через CDN Fastly, без дополнительной настройки

⚡ Cache-Control

Для статичных файлов (картинки, шрифты, CSS с версией в имени) ставьте долгий кэш — например, max-age=31536000 (год). Браузер не будет перекачивать их при следующем визите.

04 / Критический CSS

Критический CSS: что это и зачем

Показываем экран за миллисекунды, а не секунды

Браузер не может отрисовать страницу, пока не получит и не обработает весь CSS-файл — даже если стили нужны только для футера, который пользователь ещё не видит. Критический CSS — это стили только для первого экрана (above the fold), вставленные прямо в <head> страницы, а остальной CSS подгружается уже после.

01
Выделите стили первого экранаТо, что видно без прокрутки — шапка, hero-блок, первая секция
02
Вставьте их inline в <style> внутри <head>Браузеру не нужно ждать отдельный файл, чтобы отрисовать первый экран
03
Остальной CSS подключите асинхронноНапример, через <link rel="preload" as="style"> — не блокирует рендер

Важно: для небольших сайтов (одностраничники, лендинги) эффект от критического CSS обычно заметен слабее, чем от оптимизации картинок — начинайте с них.

05 / Измерение

Как измерить скорость сайта

Без замера оптимизация — гадание

  • PageSpeed Insights — бесплатный инструмент Google, показывает реальные метрики Core Web Vitals с мобильных устройств
  • Lighthouse — встроен в DevTools Chrome (вкладка Lighthouse), удобно проверять локально при разработке
  • WebPageTest — детальный водопад загрузки по шагам, полезен, когда непонятно, что именно тормозит

Главные метрики, на которые смотрит Google: LCP (когда отрисовался главный контент), CLS (насколько страница «прыгает» при загрузке) и INP (как быстро сайт отвечает на клик).

06 / FAQ

Частые вопросы

Короткие ответы на главное

Какой результат PageSpeed считается хорошим?

90+ на мобильной версии — отличный результат. 70–90 — нормально для большинства сайтов. Ниже 50 обычно означает тяжёлые неоптимизированные картинки.

CDN платный?

Базовый тариф Cloudflare бесплатный и покрывает большинство небольших и средних сайтов. Платные планы нужны для расширенной аналитики и правил.

Стоит ли оптимизировать шрифты?

Да — используйте font-display: swap, чтобы текст не был невидимым во время загрузки шрифта, и подключайте только реально используемые начертания.
